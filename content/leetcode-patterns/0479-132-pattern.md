## 1. What it is

Given an array `nums`, determine whether it contains a "132 pattern": three indices `i < j < k` such that `nums[i] < nums[k] < nums[j]`. The name comes from the relative ranking of the three values (smallest, largest, middle), not their actual values. Example: `nums = [3, 1, 4, 2]` → `true` (`i=1` (`1`), `j=2` (`4`), `k=3` (`2`): `1 < 2 < 4`).

## 2. Why & when

Scanning from the **right** and asking "is there a `nums[j] > nums[k]` pair where some earlier value is smaller than `nums[k]`" turns this into a next-smaller-style query, from the [monotonic-stack signal](0466-monotonic-stack-signal-next-greater-smaller-element-or-histo.md) family. The twist: the stack tracks candidate "2" values (the `nums[k]` role) while a separate running variable tracks the best "3" seen so far. Constraints: up to 200,000 elements.

## 3. Core concept

**Key idea:** scan `nums` from right to left. Maintain a decreasing stack of candidate values for the "2" position (potential `nums[k]`), and a running variable `thirdMax` for the best confirmed "2" value seen so far (renamed here to avoid confusion — it plays the role of `nums[k]`, the smallest of the pattern, found to the right of a bigger "3"). If the current value is less than `thirdMax`, a valid "1 < 3, 2" pattern is found — return `true` immediately, since the current value plays "1," `thirdMax` plays "2" (already confirmed to sit between a bigger value further right), and that bigger value plays "3."

**Steps:**
1. Scan `nums` from the last index to the first.
2. Maintain a stack (decreasing) and a variable `thirdMax = Integer.MIN_VALUE`.
3. At each index `i`: if `nums[i] < thirdMax`, a "132 pattern" exists — return `true` (the current value is "1," `thirdMax` is "2," and the value that popped to set `thirdMax` is "3").
4. While the stack is not empty and its top is less than `nums[i]`, pop it and set `thirdMax` to that popped value (it becomes the best confirmed "2" so far, since `nums[i]` is bigger than it — playing "3").
5. Push `nums[i]`.
6. If the scan finishes with no early return, return `false`.

**Why popping and updating `thirdMax` finds the best "2":** every time a bigger value (playing "3") pops a smaller one (playing "2"), that smaller one is now guaranteed to have a bigger value to its right — exactly what "132" requires between positions `j` and `k`. Keeping the maximum such popped value gives the best (least restrictive) "2" to test future "1" candidates against.

## 5. Runnable example

**Level 1 — Brute force.** Try every triple `i < j < k` and check `nums[i] < nums[k] < nums[j]`. O(n³), or O(n²) with a precomputed suffix maximum.

**KEY INSIGHT:** scanning right to left, the best possible "2" value found so far is always the largest value that some bigger value (to its right) has already confirmed — tracking just that one number, `thirdMax`, is enough to test every candidate "1" in O(1).

**Level 2 — Optimal.** Right-to-left monotonic stack with a running `thirdMax`, O(n).

**Level 3 — Hardened.** Handles arrays with no valid pattern, and duplicate values (strict inequalities matter).

```java
// Pattern132.java
import java.util.*;

public class Pattern132 {

    // Level 1: brute force, O(n^2) using precomputed suffix max as "3" candidate
    static boolean bruteForce(int[] nums) {
        int n = nums.length;
        for (int j = 0; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (nums[k] < nums[j]) {
                    for (int i = 0; i < j; i++) {
                        if (nums[i] < nums[k]) return true;
                    }
                }
            }
        }
        return false;
    }

    // Level 2 & 3: right-to-left monotonic stack, O(n)
    static boolean find132pattern(int[] nums) {
        Deque<Integer> stack = new ArrayDeque<>(); // decreasing, candidate "2" values
        int thirdMax = Integer.MIN_VALUE; // best confirmed "2" value (renamed to avoid clashing with nums[k])

        for (int i = nums.length - 1; i >= 0; i--) {
            if (nums[i] < thirdMax) {
                return true; // nums[i] is "1", thirdMax is "2", the value that set it is "3"
            }
            while (!stack.isEmpty() && stack.peek() < nums[i]) {
                thirdMax = stack.pop();
            }
            stack.push(nums[i]);
        }
        return false;
    }

    public static void main(String[] args) {
        System.out.println(find132pattern(new int[]{3, 1, 4, 2}));       // true
        System.out.println(bruteForce(new int[]{3, 1, 4, 2}));           // true
        System.out.println(find132pattern(new int[]{1, 2, 3, 4}));       // false (strictly increasing)
        System.out.println(find132pattern(new int[]{-1, 3, 2, 0}));      // true
    }
}
```

**How to run:** save as `Pattern132.java`, then run `java Pattern132.java`.

## 6. Walkthrough

Trace `find132pattern({3, 1, 4, 2})`, scanning right to left (`i = 3, 2, 1, 0`):

| i | nums[i] | thirdMax before | check `nums[i] < thirdMax` | stack before | pops | stack after | thirdMax after |
|---|---|---|---|---|---|---|---|
| 3 | 2 | -inf | false | [] | none | [2] | -inf |
| 2 | 4 | -inf | false | [2] | pop 2 (2<4) | [4] | 2 |
| 1 | 1 | 2 | `1 < 2` → **true** | — | — | — | — |

At `i=1`, `nums[1]=1` is less than `thirdMax=2`, so the method returns `true` immediately. This corresponds to `i=1` (value `1`, the "1"), `thirdMax=2` from index `3` (the "2"), and `nums[2]=4` (the "3") — the three indices `1 < 2 < 3` satisfy `nums[1]=1 < nums[3]=2 < nums[2]=4`.

## 7. Gotchas & takeaways

> Gotcha: naming the running variable `nums[k]` or reusing `nums[i]`-style names causes confusion between the pattern's positional roles ("1," "2," "3") and the array's actual indices — keep them mentally separate, since "2" (`thirdMax`) is not literally `nums[k]` at a fixed index, it is the best candidate found so far.

- The pattern's name refers to relative rank (small, large, middle), not literal values `1`, `3`, `2`.
- Track only the single best confirmed "2" value (`thirdMax`) — you never need to know which specific "3" produced it.
- Time: O(n) — right-to-left scan, amortized stack operations, same 2n bound as any monotonic-stack pattern.
